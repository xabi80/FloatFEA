# The dev toolchain, pinned EXACTLY (R824, directive FP2).
#
# ONE FILE, USED BY CI AND BY THE DOCUMENTED LOCAL SETUP, so that a green here means a
# green there. `pyproject.toml`'s `[project.optional-dependencies] dev` carries FLOORS
# (`mypy>=1.9`), which is what a human reads; this file carries the exact versions a run
# must use.
#
# WHY IT EXISTS, AND THE COST IS MEASURABLE. At R1 step 1 the tree was green locally on
# `ruff`, `black` and `mypy`, and CI's `mypy` FAILED on the same commit:
#
#     floatfea/run/config.py:67: error: Unused "type: ignore" comment  [unused-ignore]
#
# `types-PyYAML` types `construct_object` at the version CI resolved and leaves it untyped
# at the version installed locally, so a narrow `type: ignore` was REQUIRED here and
# UNUSED there. Both runs were correct about their own toolchain. The red then SKIPPED
# CI's `unit tests` and `guards and meta-tests` steps, so that one version gap also meant
# CI had never run R1's unit tests or guards at all.
#
# Five of the six tools differed. Measured at that commit:
#
#     tool            local            CI resolved
#     mypy            1.20.2           2.4.0          <- a different MAJOR version
#     ruff            0.15.12          0.17.1
#     pytest          9.0.3            9.1.1
#     hypothesis      6.152.2          6.170.0
#     types-PyYAML    6.0.12.20260408  6.0.12.20260906
#     black           24.10.0          24.10.0        <- the only one that matched
#
# PINNED FORWARD, TO THE SET CI RESOLVED, not backward to the local one. `ci.yml` makes CI
# canonical for `tests/regression`, so pinning backward would make CI stop testing what it
# tests today and would hide the next such gap instead of closing it.
#
# To change a pin: change it here, run the four local commands, and let CI run at the same
# pin. A pin moved on one side only is the defect this file exists to prevent.
