# WHY THIS FILE EXISTS (BE3). The shipped gate poses ONE geometry in TWO
# orientations at THREE length units. Every negative control on it was designed
# by the same hand as the gate, so the coverage it demonstrates is coverage of
# the cases its author thought of. These are cases the author did not run. They
# are written down rather than left in a verdict so the next round can measure
# against them instead of re-deriving them.
#
# WHAT A PASSING SCAN MEANS. For each entry, the six constant-strain states are
# solved in the named orientation and the worst relative field error is compared
# against PATCH_TEST_EXACTNESS, and the worst recovered-resultant error against
# RESULTANT_EXACTNESS. A passing scan means every entry marked expect=hold is
# below both ceilings AND the 1e-6 single-element negative control still exceeds
# both counters at that entry. It does NOT mean the shipped test suite runs the
# entry -- the `runs_in_suite` field records that separately, and it is the
# coverage measurement.
#
# expect=hold    the ceilings are claimed to hold here
# expect=breach  measured above PATCH_TEST_EXACTNESS at this reviewer's run
# expect=raise   the configuration must RAISE, not default to a silent fallback
#
# FIELDS
#   id            stable name
#   section       circular_tube D=<m> t=<m>            (the only shape basis.kappa knows)
#   stations      total member length in m; the mesh is the gate's own ratio set
#   orient        axis | skew | vertical | in_plane_y
#   extra         orientation_node=..., roll=<rad>, I_y_over_I_z=<r>, or none
#   runs_in_suite yes | no       -- does a shipped test execute this configuration
#   expect        hold | breach
#
