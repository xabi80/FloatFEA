## What it changes, for a reader who finds this file first

the step under execution from the plan's marker and then required that step's REPORT to
exist; FR3 inverted the order, asking for the whole of FL2 to be built before the first
reviewed revision. With the marker at 2 the hook gated step 3's work against step 2's last
reviewed commit — a diff no step-3 verdict could clear, because step-3 verdicts are
written into `docs/reviews/R1/step-3.md`, a file the hook never opened. With the marker at
3 the hook refused outright, because step 3 had no report.

Measured at `5ca5496`: marker `2`; the diff the hook took against `8542d79` was 9 files
and 1654 insertions; `docs/reviews/R1/step-3.md` held **7** reviewed commits the gate could
not see. The hook's own comment documents the same shape from F6a, where "NO commit and NO
verdict could clear it" and three interim checks were forced by it. This was the second
occurrence and it cost seven.

**What had actually been ending the turns was `stop_hook_active`** — the hook allows the
continuation after it blocks once — so the exemption, not the work, was clearing the gate.
FT0 keys the marker on the REVIEW file, which under FR3 exists long before the report.

**FT1 accepts the narrowing the reviewer proposed and I relayed:** the predicate's second
limb is about a check whose SUBJECT is the commit carrying it, not one that merely reads

repair's CALLER is held by a test, and the revert-red-restore cycle covers the call site
