## G0.2 is partial, and carries a closing condition

The machine-readable frame definitions the validator checks records against do
not exist yet. Creating them now would produce a second hand-maintained copy of
`conventions.md`, and two hand-maintained copies of one convention diverge —
with the divergence surfacing as a wrong answer rather than a failing test.

The requirement is that the copy is **generated from, or tested against**, the
document. That belongs with the reader, in F1, where there is something to test
it against.

> **Closing condition: F1 CANNOT CLOSE while G0.2 is partial.**

This is stated as a condition rather than a status because **PARTIAL is how
gates die**. A deferred gate with no forcing event is carried forward one
milestone at a time until nobody remembers what it was for, and the deferral is
always individually reasonable. Binding it to F1 — the next milestone, already
in progress — means the deferral is resolved within weeks by a milestone that
cannot close around it, rather than surviving as a permanent asterisk.

The condition is concrete: F1 produces the reader and the validator, the
validator needs something to check records against, and that artifact must have
a test asserting it agrees with `docs/conventions.md`. If F1 reaches closure and
that test does not exist, F1 does not close.

## D2 — why the tag is not at `928ae47`

`docs/hsp-coupling.md` says to tag "the current known-good state". The tag sits
**three commits downstream** of the tip that existed when F0 opened, on a commit
that adds a `capytaine` declaration, a Hypothesis determinism profile, and a
lock file.

**A tag at `928ae47` would anchor G1.5 to an unprovisionable suite.** At that
commit, `capytaine` is undeclared — so `tests/validation/test_m11b_pr7_screening.py`
cannot import — and Hypothesis draws a fresh seed per run against a gitignored,
untracked example database. Neither the pass count nor the set of examples
explored is reproducible from the manifest. A gate demanding bit-identical
results across two provisionings cannot be anchored to a state that does not
provision identically twice.

### Evidence that the harness changes are result-neutral

**G1.5 cannot supply this evidence.** The gate compares the export branch
against the tag, and both sides carry the harness commit, so it is blind to it
by construction. That blindness is the whole reason D2 needs justifying in
prose. What follows is *not* a bit-identity check and must not be read as one.

**The stronger half — the simulator was not touched.**
`git diff --stat 928ae47 25de7ce -- floatsim/` is **empty**, as is the same diff
against `e69f53c`, the last commit to touch the package. The harness commit adds
a test-harness file, one dependency line, and a lock file. No line of the
integrator or the force model changed. This is a complete argument about the
*code*.

**The weaker half — behavioural corroboration.** `platform_bem.py validate`
(STEP D) reproduces the committed conditioning-detector values in the pinned
environment: `16.837 → z = 11.72` (fires, threshold 5.0) and `4.934 → z = 0.06`
(flat), against the **11.7** recorded at `docs/m11-platform-plan.md:637`.

That is **three-significant-figure agreement against a value recorded to three
figures — corroboration, not proof.** It shows the conditioning screen still
selects the same frequency slices, which is the property the hydro database
depends on. It does not show that any downstream number is bit-identical, and no
claim of that kind is made here. A dependency set did change (pandas 3.0.5 →
2.3.3 among others), so bit-level agreement was never the expectation; what is
claimed is that the change is confined to declaration and harness, and that the
one behaviour cheap enough to re-measure independently still behaves.

## Findings raised

1. **`xi[3:6]` is interpreted three ways inside FloatSim** — ZYX Euler, axis-angle,
   linearised — all feeding the same equations of motion. Escalated to
   LEVEL2-INTEGRATOR-UNWIRED as primary evidence. Puts a ~0.4% floor under G4.1
   that cannot be exported away.
2. **CoG is 37.0 mm from the body reference point**, and FloatSim assumes them
   coincident (`driver.py:222`). Omits a `m·d = 1.061 kg·m` translation–rotation
   coupling block — 4.05% coupling ratio. Offered as a candidate mechanism for
   KD-2's pitch-period gap, as a hypothesis for whoever owns KD-2.
3. **`capytaine` was an undeclared hard test dependency**, and the studies couple
   to its private API.
4. **`g = 9.81`, not 9.80665** — adopted from FloatSim, recorded so a future
   mismatch is not hunted as a mass error.
