## Six defects found: three in the tree, three of my own

1. **`floatsim` resolved by CALL ORDER.** The system interpreter carries an editable
   install pointing at a checkout 121 commits past the pin, whose `_EditableFinder` sits
   after `PathFinder` — so which of two trees answered an import depended on whether the
   worktree was put on `sys.path` first. Nine source files differ, one of them the
   radiation convolution the npz path imports directly. **No published number came from
   the wrong tree** (the solve always imports first), which is a guarantee by call order
   and therefore FR1's second head. The locked venv removes the second tree entirely and a
   refusal makes the remaining case loud.
2. **GI3(e)'s config key did not exist.** Step 0 built the env-var half; `hsp_pin`'s
   docstring named a config key the schema would have refused, and no production call site
   passed it. Three keys added (SR-78).
3. **A GI1 violation, carried to step 2**: `run_floatsim_design_waves.py` writes its case
   files *into* the pinned worktree, which GI1 forbids in the same clause that authorises
   the runs. Step 1 does not reach that path.

**And three I introduced in this step and fixed in it**, each found by reading my own diff
rather than by a test, and each now held by one: `--out` left the provenance hard-coding
`data/f4/dynamic_inputs.npz`, so an export anywhere else would ship a sidecar naming a file
it is not beside; `floatfea export` would have **silently overwritten the committed
golden**, because the shipped export configuration targets the committed location; and the
new test file's cleanup fixture globbed `examples/tmp_*.yaml` and **deleted two scratch
configurations a 25-minute measurement was running against**. A fixture that cleans up by
pattern cleans up by guess.
